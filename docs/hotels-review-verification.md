# Проверка Hotels и Review — 13 октября 2026

Изменение реализовано после независимой проверки плана агентом. Полный список выполненных сценариев: [JSON-отчёт](hotels-review-verification.json).

## Автоматические проверки

- `go test -race` — все шесть сервисов и hotelctl, включая существующие lifecycle-тесты с TCP listeners.
- `go vet` — все шесть сервисов и hotelctl.
- Отдельная сборка Hotels, Review, Booking и API Gateway с `GOWORK=off`, `GOOS=linux`, `CGO_ENABLED=0` — успешно, без зависимости от go.work.
- Buf lint/build/generate: собственные API Review/Hotels/Booking и клиенты Review → Hotels → Booking → Gateway; публичный Clay API. Для Gateway использован штатный offline target с внешним кешем imports, без third_party в репозитории.
- xo сгенерирован из изолированных PostgreSQL БД с применёнными каноническими миграциями. Пакеты ошибок и DAO сохранили проектный формат.
- Четыре skill-файла прошли quick_validate. Проверен код без JSON-тегов entity/DTO, clock-функций и сервисных ссылок на удалённые Room/Search.

Unit-тесты проверяют один batch RPC, связывание по UUID при переставленном ответе, отсутствие N+1, отсутствие/ноль рейтинга, ошибку Review, пагинацию и валидацию batch. Storage-тест проверяет один SQL с полным набором UUID и отсутствие SQL для пустого набора. hotelctl проверяет четыре независимых владельца БД, оба seed и отсутствие Kafka-конфигурации у Hotels/Review.

## Реальное взаимодействие

Запущены отдельные PostgreSQL 16, Kafka 3.9.1 и процессы Review, Hotels, Booking, API Gateway. Проверки выполнялись через настоящий HTTP Clay, generated gRPC и PostgreSQL, без подмены транспорта.

Список из трёх отелей вернул рейтинги 4.5, 4 и отсутствие оценки; в журнале PostgreSQL проверен **ровно один** batch select Review для этого HTTP-запроса. Отдельно проверены настоящий рейтинг 0, порядок страниц, пустая страница, HTTP 422 на неверные параметры, HTTP 404 на неизвестный номер, теги/площадь/вместимость и min/max.

Создание брони: CONFIRMED, повтор ключа возвращает ту же бронь, пересечение — 409, нарушение min/max — 422. При остановленном Review ListHotels/GetHotel дают 503; GetRoom/ListRooms, readiness Hotels, пустая страница, CheckAvailability и новая бронь продолжают работать. После запуска Review чтение отелей восстановилось. События двух созданных броней успешно отправлены outbox в тестовую Kafka.

Работающий k3s и его БД не изменялись. Для перехода существующего volume нужна подготовка новых БД, описанная в [инструкции](hotels-review.md). Полный request/reply Check-in в этой проверке не повторялся: его код/контракты не менялись; его тесты пройдены.
