# Проверка модели с периодом и EXCLUDE

Дата: 13 октября 2026. Проверена временная копия изменений перед переносом в основной репозиторий. Использованы отдельные PostgreSQL 16, Kafka 3.9.1 и процессы Booking, Room, API Gateway. Работающий k3s-стенд и его данные не изменялись.

## Конкуренция и атомарность

- 24 одновременные пересекающиеся брони: одна сохранённая бронь и одно событие outbox.
- 24 одновременных повтора ключа: один ID, исходный request_id, версия 1, одно событие.
- Повтор ключа с другим номером или периодом: Conflict. Ключи разных гостей независимы.
- Прямые INSERT и UPDATE с равным, вложенным, охватывающим или частично пересекающимся периодом: PostgreSQL отклоняет запись с 23P01.
- Соседние периоды [) и бронирования разных номеров разрешены.
- NULL номер/границы, пустой, обратный и бесконечный период отклоняются БД.
- Сбой после записи outbox, отмена запроса и принудительный обрыв PostgreSQL-соединения: ни бронь, ни событие не сохраняются. Повтор с тем же ключом успешен.
- Потерянный успешный ответ восстанавливается по ключу. Ограничения длительности не допускают записи при отказе.

Транзакционные проверки выполнены отдельным временным Go-тестом с `-race` на изолированной БД. Основной набор тестов репозитория остаётся unit.

## Сквозной HTTP и Kafka

Проверены CreateBooking, GetBooking, повтор неизменённого запроса, HTTP 409 для пересечения/другого состава, HTTP 422 без ключа и CheckAvailability. Ответы содержат starts_at/ends_at без slots.

При отключённом Room сохранённый повтор возвращается успешно, а новая операция завершается 503 без частичной записи. При отключённой Kafka вторая, соседняя бронь подтверждается, событие остаётся pending. Повтор ключа не добавляет событие. После восстановления Kafka обе записи обработаны: outbox_count=2, pending=0.

Оба сообщения прочитаны из самого Kafka-топика: booking.confirmed.v1, ключ равен aggregate_id, payload содержит room_id, starts_at и ends_at. Второе сообщение создано во время отключения брокера. Доставка остаётся at-least-once; эта проверка не обещает отсутствие дублей при потере ACK.

## Инструменты

- Buf format/lint/build и генерация локальных контрактов Booking/Gateway.
- xo-модель получена из реально применённой схемы. Для закреплённого xo добавлен узкий patch expression-index; EXCLUDE не снимался.
- `go test -race`, `go vet`, `go build`: все шесть сервисов и hotelctl прошли.

Машинный отчёт и прочитанные payload: [period-booking-verification.json](period-booking-verification.json).

Миграции изменены inplace. Старой учебной БД требуется явное пересоздание перед запуском новой версии; обычный redeploy не меняет уже применённую миграцию.

Исторический отчёт: после перехода на [Hotels/Review](hotels-review.md) функции каталога Room выполняет Hotels; имена сервисов выше соответствуют дате проверки.
