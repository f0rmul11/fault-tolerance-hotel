# Каталог Hotels и рейтинги Review

## Согласованный объём

Search заменяется сервисом `hotels`, Room удаляется как отдельный сервис. Новый `review` хранит только рейтинги отелей. Рейтингов номеров и API выставления оценки в этом шаге нет: данные учебные, API только для чтения. Имена Room и Hotel сохраняются как разные сущности внутри Hotels.

## Владение данными

- Hotels: Hotel (UUID, название, описание, официальная категория в звёздах, страна, город, адрес, координаты); Room (UUID, hotel_id, номер, название/категория, описание, вместимость, число комнат/кроватей, площадь, теги удобств, минимальная/максимальная длительность бронирования).
- Review: Rating отеля (hotel_id, сумма пользовательских звёзд, число оценок). Средний рейтинг — сумма / количество, от 0 до 5. Ноль оценок означает «нет рейтинга», а не оценку 0. Официальные звёзды отеля и пользовательский рейтинг — разные поля.
- Booking: гость, период, статус, идемпотентность и атомарная занятость номера. Получает min/max из Hotels до своей транзакции. Check-in и обмен Kafka сохраняются.

## Контракты

HotelsService: ListHotels (limit/offset с разумными пределами), GetHotel, ListRooms(hotel_id), GetRoom(room_id). Hotel не содержит вложенных номеров. Room содержит условия длительности, поэтому существующие сценарии Booking используют GetRoom/ListRooms без дополнительных RPC и без обращения к Review.

ReviewService: GetHotelRatings(repeated hotel_ids), один batch SQL `where hotel_id = any($1)` в своей БД. Ответ — рейтинги найденных ID с числом оценок. Отсутствующая строка означает отсутствие оценок. Пустой список не обращается к БД. Неизвестный hotel_id не требует сетевой проверки существования отеля.

ListHotels загружает страницу из своей БД, одним вызовом Review получает рейтинги всех ID этой страницы и объединяет результат по UUID. GetHotel использует тот же batch-клиент с одним ID. Пустая страница не вызывает Review. GetHotel явно получает рейтинг по UUID и вызывает Hotel.SetRating, возвращая саму сущность. Узкий application service обогащает список тем же методом. DTO содержит только Rating, без обёртки над Hotel. Рейтинг не сохраняется в БД Hotels. При ошибке Review возвращается корректная ошибка, выдуманный нулевой рейтинг не подставляется.

API Gateway получает четыре публичных GET через Clay: /v1/hotels, /v1/hotels/{hotel_id}, /v1/hotels/{hotel_id}/rooms, /v1/rooms/{room_id}. Это только proxy, без use case, own errors и ручного HTTP. Review доступен внутри стенда по gRPC.

## Реализация

1. Проверить план отдельным агентом: границы, батч, отказ Review, контракты и конфигурацию.
2. Перенести существующий каркас Room и его каталог в Hotels, расширить сущности/миграцию/seed. Удалить Search и Room из кода и active конфигурации. Сохранить UUID учебного отеля/номеров для сценариев Booking.
3. Создать Review с domain, DAO поверх xo, одним batch storage/use case/handler, seed и собственной БД. Формат ошибок/инициализации взять из существующих сервисов.
4. Реализовать Hotels use cases, обогащение рейтингом, gateway Review, тонкие RPC. Подключить Booking к Hotels, добавить Clay proxy каталога.
5. Buf генерирует локальные и внешние контракты; xo генерируется с изолированной мигрированной БД. Никакой third_party и ручного редактирования generated-файлов.
6. Обновить go.work, Makefile, hotel.yaml, service конфиги, Docker/Kubernetes, hotelctl, миграции/seed job, правила и актуальную документацию. Существующий запущенный кластер и его данные не сбрасываются.
7. Проверить unit/race/vet затронутых модулей, Buf build/generation; реальным PostgreSQL проверить миграции и batch запрос. В изолированном запуске проверить HTTP каталога, рейтинг/нет рейтинга, ошибки ID, создание брони с min/max и пересечением. Остановка Review должна ломать только чтение обогащённых отелей, а GetRoom/ListRooms и создание брони должны продолжать работать.

## Ограничения этапа

Нет CRUD каталога, записей оценок, полнотекстового/геопоиска, новых событий, кешей, ретраев или метрик. Данные каталога и рейтингов задаются seed. Новый состав стенда: api-gateway, booking, check-in, hotels, review, notification.
