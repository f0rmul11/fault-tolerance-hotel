# Проверка разделения Booking, Room и Availability — 12 октября 2026

Проверен текущий код на изолированных PostgreSQL 16 и Kafka 3.9.1. Четыре реальных процесса: Clay Gateway → Booking → Room/Availability. Основной k3s-стенд в этом проходе не переразворачивался, его данные не сбрасывались.

| Проверка | Результат |
| --- | --- |
| Каталог | Room.GetHotel/ListRooms/GetRoom читают собственную БД, seed содержит 10 номеров |
| Создание и чтение | HTTP 200 CONFIRMED v2; отдельный ACTIVE Reservation с собственным ID и тем же booking_id; оба слота сохранены |
| Пересечения | Восемь конкурентных HTTP POST: один успех, семь 409. PostgreSQL-тест: 24 претендента, один резерв |
| Набор слотов | Конфликт одного слота откатывает весь набор; разрывы и смежные интервалы свободны |
| Условия Room | Для тестового номера min=2h/max=6h: 2h приняты, 24h отклонены. У другого номера с min=12h слот 2h отклонён; Booking сохраняет REJECTED |
| Повтор Reserve | 24 повтора одной команды: один ID резерва, одна запись, одно событие; изменение условий не меняет сохранённый результат |
| Один booking_id, два номера | Один успех и один конфликт, не два резерва |
| Release | Безопасный повтор, номер снова доступен, поздний Reserve после Release отклонён; 20 гонок Reserve/Release заканчиваются RELEASED |
| Ошибка outbox | Reserve и Release откатывают состояние и событие; Booking не выдаёт CONFIRMED после ошибки финальной записи/commit |
| Kafka отключена | Создание остаётся HTTP 200 CONFIRMED; два исходных события долговечно сохранены с processed_at=null |
| Kafka восстановлена | Из обоих Kafka topics прочитаны сообщения с исходными event_id; обе записи outbox помечены обработанными |
| Авторизация Gateway | Проверяются только роли; actor/request ID передаются Booking. Тесты проверяют owner-ошибки и metadata |

`go test -race`, `go vet`, `go build` прошли для всех семи сервисов и hotelctl. Дополнительные PostgreSQL integration-тесты прошли для Availability и Booking. Proto сгенерированы Buf, xo — из актуальной схемы PostgreSQL. Для шлюза BSR вернул HTTP 403: проверен `generate-offline` с закреплёнными внешними исходниками из README шлюза, без third_party в репозитории.

Результат не означает exactly-once или готовый production lifecycle. Доставка at-least-once, возможны дубликаты/перестановки; автоматическое восстановление PENDING/UNCERTAIN, публичная идемпотентность и отмена клиентской брони ещё отсутствуют. Release — внутренний примитив Availability; его прямой вызов не меняет Booking. Каталог пока read-only, ограничения передаются как снимок для команды.

Исторический отчёт: после перехода на [Hotels/Review](hotels-review.md) функции каталога Room выполняет Hotels; имена сервисов выше соответствуют дате проверки.
