# Hotels и Review

`hotels` владеет каталогом отелей и номеров; `review` — рейтингами отелей. Всего в стенде шесть сервисов. История перехода от Room/Search сохранена отдельно: [план](hotels-review-plan.md).

## Данные

Hotel: UUID, название/описание, официальные stars (0 — не присвоены), страна/город/адрес, широта/долгота. Room: числовой ID, hotel_id (UUID), number, название, room_type, описание, вместимость, количество комнат/кроватей, площадь в м², amenities, min/max длительность. ID номера хранится в bigint и передаётся строкой, например "1"; number — обозначение внутри отеля, например "101". room_type — строковое значение типа, например "Standard", без отдельного ID. Отсутствие max_duration_seconds означает отсутствие верхнего предела.

Review хранит целые total_stars и review_count для hotel_id. Возвращает среднюю пользовательскую оценку 0–5, число оценок. Rating в публичном ответе отсутствует при отсутствии оценок; 0 с положительным review_count является оценкой. Это не официальные звёзды и не оценки номеров. Запись оценок/каталога пока не реализуется, данные задаёт seed.

## Чтение через API Gateway

| HTTP | Результат |
|---|---|
| GET /v1/hotels?limit=20&offset=0 | Базовые отели без вложенных номеров, с рейтингами |
| GET /v1/hotels/{hotel_id} | Один отель с рейтингом |
| GET /v1/hotels/{hotel_id}/rooms | Номера отеля с удобствами и min/max |
| GET /v1/rooms/{room_id} | Конкретный номер со всеми полями каталога |

Список отелей сортируется по UUID, limit 1–100, по умолчанию 20. Отрицательное смещение/невалидный UUID — HTTP 422, отсутствующий конкретный ресурс — 404. Список комнат неизвестного отеля — пустой список, без дополнительного запроса существования. Каталог публичный; роли гостя/оператора остаются у Booking/Check-in.

Hotels читает страницу из своей БД, собирает все UUID и делает один GetHotelRatings. Review выполняет один `select ... where hotel_id = any($1::uuid[])`. Объединение по UUID сохраняет порядок каталога. Пустая страница не вызывает Review. У списка нет N+1. Use case возвращает сущности Hotel с рейтингом, установленным через SetRating; отдельной DTO-обёртки нет. DTO Rating содержит значение и число оценок. Рейтинг не сохраняется в БД Hotels. В Review нет произвольного ограничения числа ID в batch.

Ошибка Review возвращается при чтении отелей (например, 503 при отключённом процессе). GetRoom/ListRooms, readiness Hotels, создание брони и CheckAvailability продолжают работать. Booking вызывает Hotels через gateway до своей транзакции; GiST, идемпотентность, outbox и Check-in request/reply сохраняются.

## Генерация и запуск

Контракты локальные: services/hotels/api, services/review/api, публичный API — services/api-gateway/api. `make generate-booking-api` генерирует Review → Hotels → Booking → Check-in → Gateway. Generated xo создаётся из своей мигрированной БД, обычная генерация не сбрасывает данные.

hotel.yaml: review получает прежний gRPC-порт Room 9093, hotels — прежний Search 9095; admin 8084 и 8086. Каждому владельцу передаётся только свой DSN. Kafka нужна Booking, Check-in и Notification. Migration Job сначала применяет миграции в public четырёх отдельных PostgreSQL, затем seeds Hotels и Review.

У Hotels и Review отдельные PostgreSQL, Service, PVC и Secret, как и у Booking/Check-in. Контейнер создаёт только свою БД через POSTGRES_USER/POSTGRES_DB; все таблицы — public. Общего postgres и init.sql больше нет. Подробности запуска — [зависимости стенда](../deploy/booking-dependencies/README.md). Старые объекты/тома кластера не удаляются обычным apply, автоматического переноса старых схем нет.

Учебные данные: отели имеют заранее сгенерированные UUID v4; номера имеют системные ID 1–11. В первом отеле ID 1 имеет number="101", во втором отеле ID 11 также имеет number="101": одинаковый номер двери не означает один объект. Второй отель имеет семейный номер с max=7 суток; третий — без оценок. Первый рейтинг 4.5 (10 оценок), второй 4 (4 оценки). Во всех seed номерах min=12 часов.

Идентификаторы и снимок номера в API/Kafka: [identifiers.md](identifiers.md).
