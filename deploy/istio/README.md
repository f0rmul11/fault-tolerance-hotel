# Istio 1.31.3 для канарейки Review

`crds/` и `controller/` — локальные манифесты, которые `hotelctl canary setup review` применяет через Kubernetes API. Никаких установочных скриптов, Helm или istioctl на машине пользователя не требуется. Istiod запускается в одной реплике; ingress gateway и дополнительные приложения не устанавливаются.

Источник: [официальный релиз Istio 1.31.3](https://github.com/istio/istio/releases/tag/1.31.3). Манифесты предварительно получены командой `istioctl manifest generate -f deploy/istio/profile.yaml` этой версии и разделены по ресурсам. `profile.yaml` сохранён для воспроизводимого обновления разработчиком и при запуске стенда не применяется.

Адаптация к стенду: HPA исключён, namespace задан явно, scope правил webhook — `*`. У validating webhook не фиксируется `failurePolicy`: этим полем, как и CA bundle, управляет Istiod. CRD и шаблон инъекции сохранены из поставки, вручную их редактировать не нужно.

При переходе со старого установочного скрипта hotelctl забирает управление описанными в YAML полями инфраструктуры через server-side apply. Это относится только к инфраструктуре; веса трафика остаются под управлением Argo Rollouts.
